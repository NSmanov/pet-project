# Руководство по Участию в Разработке

Спасибо за интерес к участию в разработке Системы Управления Задачами! Этот документ предоставляет руководства и инструкции для участия.

## Начало Работы

1. Сделайте Fork репозитория на GitHub
2. Клонируйте свой fork локально
3. Настройте окружение для разработки
4. Создайте новую ветку для вашей функции или исправления
5. Внесите изменения
6. Напишите или обновите тесты
7. Убедитесь, что все тесты проходят
8. Отправьте pull request

## Настройка Окружения Разработки

### Требования

- Java 21
- Maven 3.8+
- PostgreSQL 13+
- Docker (для TestContainers)
- Git
- IDE (рекомендуется IntelliJ IDEA)

### Шаги Настройки

```bash
# Клонируйте свой fork
git clone https://github.com/YOUR_USERNAME/task-management.git
cd task-management

# Добавьте upstream remote
git remote add upstream https://github.com/ORIGINAL_OWNER/task-management.git

# Установите зависимости
mvn clean install

# Запустите тесты
mvn test
```

- Используйте осмысленные имена переменных и методов
- Держите методы небольшими и сфокусированными (желательно < 20 строк)
- Используйте аннотации Lombok для сокращения шаблонного кода

- Максимальная длина строки: 120 символов

## Git Workflow

### Именование Веток

- Feature: `feature/описание-функции`
- Bugfix: `bugfix/описание-бага`
- Hotfix: `hotfix/описание-hotfix`
- Documentation: `docs/описание-изменений`

Примеры:
- `feature/add-task-tags`
- `bugfix/fix-date-formatting`
- `docs/update-api-examples`

### Сообщения Коммитов

Следуйте спецификации [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <subject>

<body>

<footer>
```

Типы:
- `feat`: Новая функция
- `fix`: Исправление бага
- `docs`: Изменения в документации
- `style`: Изменения стиля кода (форматирование и т.д.)
- `refactor`: Рефакторинг кода
- `test`: Добавление или обновление тестов
- `chore`: Задачи обслуживания

Примеры:

```
feat(api): add task filtering by priority

Добавлен новый endpoint для фильтрации задач по уровню приоритета.
Включает модульные и интеграционные тесты.

Closes #123
```

```
fix(service): handle null description in task creation

Ранее null описания вызывали NullPointerException.
Теперь по умолчанию используется пустая строка.

Fixes #456
```

## Руководство по Тестированию

### Покрытие Тестами

- Стремитесь к покрытию кода не менее 80%
- Пишите модульные тесты для всех методов сервисов
- Пишите интеграционные тесты для всех API endpoints
- Включайте как позитивные, так и негативные тест-кейсы

### Структура Тестов

Используйте паттерн AAA (Arrange-Act-Assert):

```java
@Test
@DisplayName("Should create task successfully")
void shouldCreateTaskSuccessfully() {
    // Arrange
    CreateTaskRequest request = CreateTaskRequest.builder()
            .title("Test Task")
            .priority(TaskPriority.HIGH)
            .build();

    when(taskRepository.save(any(Task.class))).thenReturn(testTask);

    // Act
    TaskDto result = taskService.createTask(request);

    // Assert
    assertThat(result).isNotNull();
    assertThat(result.getTitle()).isEqualTo("Test Task");
    verify(taskRepository, times(1)).save(any(Task.class));
}
```

### Запуск Тестов

```bash
# Все тесты
mvn test

# Только модульные тесты
mvn test -Dtest=*Test

# Только интеграционные тесты
mvn test -Dtest=*IntegrationTest

# Конкретный тестовый класс
mvn test -Dtest=TaskServiceImplTest

# С отчетом о покрытии
mvn clean test jacoco:report
```

## Процесс Pull Request

### Перед Отправкой

1. Убедитесь, что все тесты проходят
2. Обновите документацию при необходимости
3. Добавьте тесты для новых функций
4. Убедитесь, что код следует руководствам по стилю
5. Сделайте rebase на последний upstream main

```bash
git fetch upstream
git rebase upstream/main
```

### Заголовок PR

Используйте тот же формат, что и для сообщений коммитов:

```
feat(api): add task filtering by priority
```

### Процесс Ревью

1. Отправьте ваш PR
2. Дождитесь прохождения CI проверок
3. Отреагируйте на обратную связь ревьюеров
4. Запросите повторное ревью после внесения изменений
5. PR будет объединен после одобрения

## Руководство по Code Review

### Для Ревьюеров

- Будьте уважительны и конструктивны
- Сосредоточьтесь на коде, а не на человеке
- Объясните, почему вы предлагаете изменения
- Одобрите, если все выглядит хорошо

### Для Контрибьюторов

- Не принимайте обратную связь на личный счет
- Задавайте вопросы, если что-то неясно
- Вносите запрошенные изменения оперативно
- Благодарите ревьюеров за их время

## Процесс Релиза

Этот проект следует семантическому версионированию (SemVer):

- MAJOR версия: Критические изменения
- MINOR версия: Новые функции (обратно совместимые)
- PATCH версия: Исправления багов

## Коммуникация

- **Issues**: Для отчетов об ошибках и запросов функций
- **Pull Requests**: Для вклада в код
- **Discussions**: Для вопросов и общих обсуждений

## Лицензия

Участвуя в проекте, вы соглашаетесь, что ваш вклад будет лицензирован под той же лицензией, что и проект.
